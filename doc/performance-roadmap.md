# План повышения скорости и качества загрузки (osov.by)

## Цели
- Снизить время рендера первого экрана на мобильных устройствах.
- Улучшить Core Web Vitals: LCP, INP, CLS.
- Уменьшить вес и блокирующее влияние JS/CSS.
- Повысить стабильность и повторяемость результата через кеширование и сборку.

## Приоритеты
1. Быстрые победы (1-2 дня): скрипты, lazy-loading, размеры изображений, кеш-headers.
2. Средний этап (2-5 дней): Vite-сборка, минификация, разбиение ассетов, оптимизация шрифтов.
3. Прод этап (1-2 дня): Brotli/Gzip, OPcache, проверка конфигурации кеша и revalidation.
4. Контроль качества (постоянно): повторные PSI/Lighthouse замеры и сравнение метрик.

## Этап 1. Быстрые изменения
- Убрать глобальное подключение тяжелых JS-плагинов из общего layout.
- Подключать плагины только на страницах, где они реально используются (`@push('scripts')`).
- Добавить `loading="lazy"` для не-критичных изображений.
- Для hero-изображения: `fetchpriority="high"` и фиксированные `width/height`.
- Прописать/проверить browser cache headers для статики.

## Этап 2. Сборка фронта и уменьшение веса
- Перенести CSS/JS в Vite-бандлы с минификацией.
- Включить versioning (hash в имени файла) для безопасного долгого кеша.
- Сократить неиспользуемые стили/плагины.
- Перейти на формат изображений WebP/AVIF там, где это возможно.
- Настроить `srcset/sizes` для адаптивной выдачи изображений.

## Этап 3. Сервер и backend-производительность
- Расширить кеширование тяжелых выборок для публичных страниц.
- Проверить и убрать N+1 запросы в списках/категориях.
- Проверить OPcache на проде.
- Включить Brotli (или Gzip, если Brotli недоступен) для HTML/CSS/JS/JSON.

## Этап 4. Контроль результата
- После каждого этапа фиксировать показатели PSI mobile/desktop.
- Отдельно отслеживать LCP, INP, CLS и TTFB.
- Откатить/пересмотреть изменения, которые дают регресс UX или SEO.
